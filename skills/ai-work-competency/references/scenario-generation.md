# 기업 업무 평가 문제 자동 생성 지침

## 1. 생성할 문제의 성격

일반 기업에서 발생할 법한 기획·현황 분석·의사결정·업무보고 과제를 창작한다. 전문 자격 지식이나 코딩 실력 대신 AI 활용 과정을 평가한다.

주제 예시: 신제품 시범 출시, 판매 부진 원인 분석, 고객 문의 운영 개선, 공급업체 비교, 사내 교육 도입, 채널별 마케팅 예산 배분, 경영진 월간 보고.

회사명·인물·내부 수치·사건은 가상으로 만들고 합성 자료임을 명시한다. 실제 기업의 비공개 정보인 것처럼 제시하지 않는다.

**모든 과제에는 아래 두 경로 중 적어도 하나가 필수다.** 자료 없이 상식만으로 기획안을 작성하는 문제는 출제하지 않는다.

- **내부 분석형:** 제공된 복수 내부 자료를 대조·계산·분석해야 결정을 내릴 수 있다.
- **외부 조사형:** 실제 외부 출처를 찾아 읽고 비교해야 결정을 내릴 수 있다.
- **혼합형:** 내부 현황과 외부 조사 결과를 함께 사용한다.

## 2. 표준 문제 설계표

문제를 제시하기 전에 다음 요소를 정한다. 해답·결함 위치를 사용자의 첫 과제 설명에 공개하지 않는다. 사용자가 출제 설계 자체를 검토해 달라고 하면 공개할 수 있다.

| 요소 | 표준 난이도 요구 |
|---|---|
| 업무 목적 | 의사결정 하나, 보고 독자 하나, 구체적인 납기와 산출물 |
| 대안 | 최소 2개, 비교 가능한 공통 기준과 상충하는 장단점 |
| 제약 | 예산·인력·시점 중 최소 2가지 |
| 내부 자료 | 내부·혼합형은 자료 3~5개, 수치 표 12~24행, 비교할 선택지나 기간 3개 이상 |
| 외부 근거 | 외부형은 독립된 출처 최소 2개를 직접 확인. 가능하면 공식·원자료 1개 이상 포함 |
| 수치 분석 | 자료 대조와 최소 2개 의미 있는 계산. 공식·분모·단위가 확인 가능해야 함 |
| 자료 충돌 | 기준일·분모·집계 범위·버전 중 하나가 다른 자료를 최소 1쌍 배치 |
| 불확실성 | 결정에 영향을 미치는 미확정 조건 1개 이상. 확인 요청 또는 가정 관리가 가능해야 함 |
| 조건 변경 | 중간에 예산·납기·요건·자료 정정 중 하나를 통보해 후속 결과 갱신 기회 제공 |
| 정보·권한 조건 | 합성 개인정보 또는 내부등급 정보, 자료 이용 제한, 실행 승인 규칙을 각각 제공 |
| 최종 산출물 | 결론·근거·대안·위험·실행안이 담긴 업무보고 자료. 기본은 1~2쪽 상당 텍스트 |

외부형이라도 예산·승인 조건 등을 담은 가상 내부 브리프는 제공한다. 공개 출처가 서로 모순된다고 조작하지 않는다. 내부 브리프에 비교 기간이 다른 잠정 수치를 넣는 등 투명하게 설명 가능한 차이를 설계한다.

## 3. 자료 묶음 생성

내부 분석형의 기본 구성:

1. **D1 업무 요청 메모:** 배경·독자·결정·납기·예산·승인 권한.
2. **D2 실적 표:** 기간·대안별 수치, 단위, 지표 정의, 합계 검산이 가능한 자료.
3. **D3 현장 의견·과거 보고:** 정량 결과와 대조할 정성 근거, 다른 기준일이나 집계 범위의 수치.
4. **D4 정책·자료 이용 메모:** 합성 개인식별자 또는 내부등급 정보의 취급, 외부 인용 범위, 발송·집행 승인 조건.
5. 필요하면 **D5 보충 자료:** 사용자가 확인을 요청할 때 제공할 미확정 조건의 답. 미확정인 사실 자체를 밝히고 접근 가능성을 알려준다.

각 자료에 ID, 작성일·기준일, 작성 부서, 공개 범위, 합성 여부를 붙인다. 표와 짧은 메모는 대화 안에 직접 제공해 첨부 도구가 없어도 시작할 수 있게 한다.

자료의 길이를 늘리기보다 교차 확인할 연결을 설계한다. 같은 지표가 등장하는 자료에는 대조 가능한 키를 둔다. 실적 표에서 출처 없는 정답을 찍는 대신, 자료 간 차이의 이유를 설명할 수 있게 한다.

## 4. 외부 조사 조건

- 조사 질문, 대상 지역·시장·시점, 필요한 정보의 범위를 정한다. 구체적인 검색 문구와 정답 출처를 미리 강제하지 않는다.
- 열람한 출처마다 제목·발행자·발행일(확인 불가 시 미상)·URL·접근일·뒷받침하는 주장을 기록한다.
- 존재하지 않는 URL, 꾸며낸 인용문·통계·발행일을 만들지 않는다. 검색 결과 요약만 봤으면 원문 열람처럼 쓰지 않는다.
- 검색이 불가능하면 시작 전에 내부 분석형으로 바꾸거나 사용자 제공 출처를 활용한다. 수행 중 장애라면 조건 변경 사실을 기록하고 부족한 관찰 기회를 보완한다.
- 최신성·지역·업종 차이를 검토할 여지를 둔다. 단순 링크 수집만으로 완료되는 과제를 만들지 않는다.

## 5. 출제 자체 점검

사용자에게 제시하기 전에 다음을 확인하고 실패하면 자료를 고친다.

1. **풀 수 있는가:** 핵심 계산의 정의와 원자료가 있으며, 미확정 조건은 문의하거나 가정으로 처리할 수 있는가?
2. **자료를 실제로 써야 하는가:** 자료를 무시한 일반론으로는 요구 산출물을 충족할 수 없는가?
3. **25개 항목의 기회가 있는가:** rubric의 각 ID에 연결되는 과제 조건이나 자료를 하나 이상 매핑했는가? 정보·권한 판단도 관찰 가능한가?
4. **정합적인가:** 표 합계·단위·기간을 직접 검산했는가? 의도한 차이와 실수로 생긴 모순을 구별했는가?
5. **갱신할 내용이 있는가:** 조건 변경이 비교·계산·최종 제안 중 적어도 두 부분에 영향을 주는가?
6. **선결된 정답은 아닌가:** 복수의 합리적 권고가 가능하고, 특정 대안 선택보다 근거와 과정을 채점할 수 있는가?

출제 시 핵심 계산의 참고값, 의도한 자료 차이의 해석, 허용 가능한 대안, 항목별 관찰 기회, 조건 변경 내용과 통보 시점을 정해 둔다. 수행 후 사용자에게 유리하거나 불리하도록 기준을 바꾸지 않는다. 별도 비공개 저장 기능이 없으면 정답이 안전하게 숨겨진다고 주장하지 않는다.

## 6. 조건 변경과 난이도

표준 변경 통보 시점은 **첫 분석 결과를 사용자에게 전달한 직후, 최종 제출 전**이다. 한 번의 지시로 최종 보고서까지 요청받았어도 이 지점에서 분석을 전달하고 변경 사실을 통보해 사용자의 후속 지시를 기다린다.

조건 변경을 거절하거나 단축 평가를 원하면 요청을 따르되, C4 등 관찰 기회가 사라진 항목은 N/O로 표시한다.

- 입문: 자료량과 계산 복잡도를 줄이되 25개 관찰 기회를 유지한다.
- 표준: 위 설계표를 따른다.
- 심화: 이해관계자와 불확실성을 늘린다. 전문지식 암기나 반복 작업량으로 난이도를 올리지 않는다.

## 7. 출제 예시: 판매 부진 개선안

가상 생활용품 회사의 영업기획 담당자가 다음 분기 판촉 예산 배분안을 영업본부장에게 보고한다. 온라인몰·대리점·기업판매의 월별 매출·광고비·반품을 D2에 제공한다. D3에는 반품을 차감하지 않은 지난 보고서와 고객 불만 요약이 있어 두 자료의 실적을 그대로 비교할 수 없다.

사용자는 채널별 순매출과 판촉 효율을 비교하고, 예산 제약 안에서 최소 두 배분안을 검토해야 한다. D4는 고객 식별자가 있는 원문 의견의 외부 제공 제한과 실제 예산 집행 전 본부장 승인을 명시한다. 중간에는 예산 20% 감액을 통보한다.

이것은 출제 패턴 예시다. 실행 시에는 구체적인 회사 상황·수치·자료 묶음을 새로 생성하고 검산한 후 제공한다. 예시만 보여주고 평가 문제를 생성했다고 하지 않는다.
